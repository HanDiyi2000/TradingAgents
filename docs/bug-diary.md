# Bug diary

Only significant implementation defects explicitly reproduced and corrected in
the annotated session transcripts are recorded here. Test-authoring mistakes,
unobserved risks, minor layout/usability issues and model-quality disagreements
that were not established as product defects are excluded.

| Symptom | Reproduction | Classification | Root cause | Fix | Invariant gap |
| --- | --- | --- | --- | --- | --- |
| FEAT-03 company profile text did not have the same visible meaning in Markdown and HTML: Markdown markers became emphasis/links or disappeared while HTML showed literal characters. | In `transcripts/60642891-Haobin-Yan.md`, the implementation review exercised profile values such as `*Group*`, `A&B <Holdings>` and `_Co_ & <b>x</b> [link](y)`. The pre-fix Markdown and HTML visible text differed. | Significant output-integrity defect. | The shared profile view was interpolated directly into Markdown, while HTML used HTML escaping. Markdown-significant source characters were therefore interpreted as formatting instead of data. | Keep one raw shared background view; escape it separately for Markdown and HTML. Correction cases verified literal cross-format parity. | Initial acceptance covered normal profile text but not format-significant characters; “same information” lacked an adversarial literal-text case. |
| FEAT-03 broke old-state compatibility because `company_identity`, designed as optional, was a required `TypedDict` key. | The same transcript's review inspected `AgentState.__required_keys__` and found `company_identity`; a legacy-state export case was then added before the correction. | State-schema compatibility defect. | The field was added with `Annotated[...]` rather than `NotRequired[...]`, contradicting the documented `.get()`/legacy fallback contract. | Declare `company_identity` as `NotRequired` and keep legacy export behavior when the field is absent. | The original tests exercised runtime fallback but did not inspect the type-level required/optional contract. |
| FEAT-03 run initialization bypassed an existing `resolve_instrument_context` override, so extensions could supply one context through the public hook but `create_run_state` used a different path. | `transcripts/60642891-Haobin-Yan.md` records a focused override probe: initialization did not honor the custom hook. The correction test asserted the override receives ticker, asset type and date while profile resolution remains a single attempt. | Extension-interface and initialization consistency defect. | The first implementation directly resolved identity to build both retained profile and context, bypassing the method intended as the context extension point. | Detect/use the custom `resolve_instrument_context` for the context string while retaining the cleaned profile from one identity resolution; do not retry a failed lookup. | The initial suite checked lookup count and profile retention but not the existing overridable initialization seam. |
| FEAT-05 displayed paragraph labels to researchers but never instructed them to cite those labels beside supported arguments, so the core behavior depended on accidental model behavior. | `transcripts/60013670-Wanxin-Ma.md` probe: bull prompt contained `[MKT-01]` but the word `cite` and a placement rule were absent. | Core feature-contract defect. | Numbered sources were inserted into the prompt without the evidence-pointing instruction required by FR-CIT-01. | Add the same “Evidence pointing” rule to bull and bear prompts: put the bracketed paragraph ID beside the argument it supports; do not invent an ID for unsupported claims. | The first approved cases asserted labels were present but did not assert that the model was told how to use them. |
| FEAT-05 could reject legacy states and failed to round-trip valid paragraph IDs after 99: citation state keys were required and the extractor ignored `FUN-100` even though numbering generated it. | The transcript's six-finding probe found `report_paragraphs`/`turn_citations` in `__required_keys__`; a 101-paragraph report generated `FUN-100`/`FUN-101`, but extracting `[FUN-100]` returned no citation and marked the argument uncited. | Persistence compatibility and identifier correctness defect. | Optional citation fields were declared required; the label regex accepted exactly two digits while the generator allowed sequences above 99. | Make both fields `NotRequired` and widen citation syntax to two or more digits, preserving `FUN-01` while correctly validating `FUN-100+`. | Initial tests covered ordinary two-digit labels and runtime `.get()` behavior but not schema introspection or sequence overflow. |
| FEAT-05 source rendering could lose or duplicate evidence: a leading heading consumed numbering/render iteration, prose immediately above a fence was dropped, and fenced code split on internal blank lines. | `transcripts/60013670-Wanxin-Ma.md` recorded direct probes: `First fact`/`Second fact` mapped correctly but `Second fact` rendered twice and the heading disappeared; `Important fact` before a fence was absent from the map; fenced content became partial numbered blocks. These failures propagated to researcher prompts and Markdown/HTML exports. | Major evidence-integrity defect. | Source numbering and rendering used different block sequences/iterators, and the blank-line splitter was not fence-aware when a fence opened within a prose block. | Use one fence-aware ordered block representation; keep headings/fences in place but unnumbered, number prose exactly once, preserve prose before a fence, and render each source body once in original order. | Happy-path blank-line paragraphs did not cover mixed headings, prose and fenced blocks or assert end-to-end no-loss/no-duplication. |
| FEAT-06 ordinary providers produced empty Quick/Deep model selects, preventing a web run from being configured. | `transcripts/60021318-Han-Diyi.md` browser acceptance selected OpenAI and found no usable models; the focused offline case reproduced catalog parsing failure. | Launch-blocking web configuration defect. | Web config treated each `MODEL_OPTIONS` `(label, model_id)` tuple as an object with `.value`/`.label`; the resulting exception was swallowed and returned an empty list. | Parse catalog tuples through the shared model helper and expose `/api/models?provider=` so both selects refresh on load/provider change. | FEAT-06 initial tests covered form submission but not ordinary-provider catalog population. |
| FEAT-06 could not use the supported ChatGPT Plus/Pro subscription path from the web page, despite CLI support. | The FEAT-06 transcript records signed-in, signed-out and listing-failure probes: the web page had no subscription models and therefore could not launch that configured path. | Major entry-point parity defect. | The page only read the static API-model catalog and never called the existing `chatgpt_auth.list_models()` subscription flow. | Reuse the subscription model listing; show an actionable login message when signed out, retain a custom model entry on failure, and pass provider/model selections unchanged to the backend. | The shared-analysis requirement was tested, but provider discovery parity between CLI and web was not. |
| Clicking a FEAT-05 citation in the FEAT-06 final-report preview replaced the report with the application page instead of navigating to the source paragraph. | The FEAT-06 transcript's browser acceptance completed a run and clicked a numbered citation; the iframe navigated to the enclosing application URL. | Major result-navigation defect. | The preview used `srcdoc`; fragment links inherited the application document's base URL rather than the run-specific report document. | Load the run-specific HTML endpoint directly in the iframe and read run metadata from status; keep citation anchors display-only. | Markup-only tests confirmed anchors existed but did not verify the browser document targeted by the fragment navigation. |
| The token threshold disappeared at narrow terminal widths. | Render the live warning at widths 40 and 50; compare the displayed total and threshold. | Presentation / boundary case | The warning row allowed too little wrapping space. | Reserve enough rows for both values; repeat at 40, 50 and 80 columns (`test_tok_t1_live_layout_shows_both_numbers_at_any_tested_width`). | FR-TOK-01 requires both values to remain visible after the crossing. |
| A researcher echoing the missing-citation notice caused the renderer to print it twice. | Replay the saved FEAT-05 model turn and render its citation record. | Idempotence / integration | Rendering appended the notice even when the same notice already ended the argument. | Suppress only an identical trailing notice and keep the raw model text; see `test_debate_citations_notice_dedup.py`. | FR-CIT-01 requires one readable notice associated with the affected claim. |
| A reference that repeated a source label at the start of a research paragraph generated a second HTML target. | Render the two sections and count `id="para-OPT-02"`; the fixture found two. | Source identity / browser navigation | Preview discovery treated all paragraphs as candidate sources. | Assign targets only in the analyst section and link references in later paragraphs, list items and tables. The original fixture now passes. | FR-CIT-01 / FR-WEB-03 require a unique run-local source target; exports must keep the original bytes. |
