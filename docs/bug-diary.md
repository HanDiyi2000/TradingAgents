# Bug diary

| Symptom | Reproduction | Classification | Root cause | Fix | Invariant gap |
| --- | --- | --- | --- | --- | --- |
| FEAT-06 web form: the Quick and Deep model boxes were empty for ordinary providers (e.g. OpenAI), so a run could not be configured from the page. | Browser acceptance on the FEAT-06 page: select OpenAI and observe both model selects contain no usable options. Offline: `test_web_models.py::test_openai_models_are_parsed_from_label_id_tuples` failed against the pre-fix code. | Implementation defect (page model options). | `cli/web/config.py::_models` read each catalog entry as an object with `.value`/`.label`, but `MODEL_OPTIONS` entries are `(label, model_id)` tuples; the resulting `AttributeError` was swallowed and every provider produced empty lists. | `_models` now unpacks the tuples positionally through `_catalog_models`/`models_for`; a `GET /api/models?provider=` endpoint refills both boxes on load and on each provider change. | None introduced; the defect was a local mapping bug. The page previously had no test for ordinary-provider model options. |
| FEAT-06 web form: choosing "ChatGPT (Plus or Pro plan)" did not list the plan's models, although the CLI supports signing in with a ChatGPT subscription and no API key. | Browser acceptance: sign in with the ChatGPT subscription, select the provider, and observe no plan models. Offline: `test_web_models.py::test_chatgpt_models_come_from_the_subscription_not_an_api_key`, `::test_chatgpt_signed_out_tells_the_user_to_log_in`, `::test_chatgpt_failure_keeps_a_clear_message_and_custom_entry`, `::test_switching_provider_to_chatgpt_refreshes_both_model_boxes`, `::test_a_chatgpt_run_reaches_the_backend_as_chatgpt_with_chosen_models` failed against the pre-fix code. | Missing feature parity with the CLI. | The page only read the static catalog. The CLI lists ChatGPT plan models live through `tradingagents.llm_clients.chatgpt_auth.list_models()`, which uses the subscription sign-in rather than `OPENAI_API_KEY`; the page never called it. | `cli/web/config.py::_chatgpt_models` lists the plan's models via `chatgpt_auth.list_models()`; a signed-out plan reports `tradingagents login chatgpt`, a listing failure shows a clear message, and the manual "Custom model ID" entry is always kept. `GET /api/models` serves it; a ChatGPT run reaches the backend as `chatgpt` with the two chosen model IDs. | None introduced. The subscription path was untested on the web; the CLI path was already covered. |
| FEAT-06 page: after one analysis the Analysis process list was very long and hard to review, because tool output and full report bodies were laid out inline. | Developer feedback from the browser acceptance run (real observation): a complete analysis produced a long scrolling page. | Usability defect (display). | Every event was rendered in full, so long reports and tool output pushed the list far past one screen; the whole right pane scrolled with the tabs. | Page pinned the configuration column and the top tabs, scrolling only the process list; long messages, tool output and reports collapse to "role/report name + one line preview" and expand on click; token warnings, errors and the debate's early-stop reason stay fully visible. Covered by `test_web_display.py`. | None introduced. Covered offline for the event-stream contract; the visual collapse/expand is a manual browser check. |
| FEAT-06 page (not observed live): a slow or repeated event poll could display the same event twice. | Reproduced only by tests, not in the live run: `test_web_display.py::test_a_repeated_cursor_read_adds_no_duplicates` and `test_web_events.py::test_a_repeated_snapshot_does_not_duplicate_prior_events`. | Latent risk (pagination), found during the display review, not an observed failure. | The poll loop could overlap requests and append without de-duplicating by cursor, so an unchanged snapshot or an in-flight repeat could re-render an event. | Polling is one request at a time keyed by run_id + cursor, with an index guard (`state.seen`) and a separate `since` cursor; the last batch is drained before switching to the report. | None introduced. Recorded as a risk fixed pre-emptively; it is not claimed to have happened in the browser run. |
