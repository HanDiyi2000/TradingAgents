# Rejected options and reopening conditions

| Alternative | Reason for rejection | Reopen when |
| --- | --- | --- |
| Combine market and options analysis | Independent selection and provenance would disappear inside the technical report. | The independent report and downstream delivery requirements change. |
| Stop a debate by keyword or number overlap | A repeated number may support a new fact; a reply may add information without introducing a new number. | A labelled evaluation demonstrates that a cheaper deterministic policy meets the same contract. |
| Count tokens by polling the UI | A later graph event can delay the first crossing and a second view would duplicate accounting. | The provider supplies an earlier reliable event than the shared completion callback. |
| Spawn a second analysis to display a report | Duplicate provider work may produce different results for the same displayed run. | Run ownership or the storage model changes enough to require a different retrieval contract. |
