# Architecture candidate evaluation

| Candidate | Driver or criterion | Evidence | Tradeoff | Decision |
| --- | --- | --- | --- | --- |
| Separate parallel analyst | Independent selection, report and delivery | Existing analyst registration and shared report writer provide extension points | Extra lookup, model work and downstream context | Selected for Feature 1 |
| Extend Market Analyst | Share existing node and report | Options output would depend on market selection and share its report identity | Fewer nodes, weaker separation of evidence | Rejected for Feature 1 |
| Structured progress judgement at the completed bull/bear pair | Detect new evidence and a first substantive reply without changing graph order | Existing bear-node handoff can evaluate once after both speakers; deterministic classifier can fail open to `UNKNOWN` | Adds one quick-tier model call from round two; live semantic accuracy remains unaccepted | Selected for Feature 2 |
| Surface token, number or citation heuristics for debate progress | Avoid an extra model judgement | Reused facts, paraphrases and citation labels are neither necessary nor sufficient to identify a first reply or new evidence | Cheaper but does not implement the semantic requirement | Rejected for Feature 2 |
| Run-local callback warning | Warn immediately when cumulative provider-reported usage first exceeds the threshold | Existing callback already owns input/output totals and is shared by model tiers | Advisory only; missing usage cannot be reconstructed | Selected for Feature 4 |
| Poll graph events or add a separate token budget controller | Keep accounting outside the callback | Graph polling can observe only after a model call; a controller would duplicate the callback's counters | Delayed warning or two competing authorities | Rejected for Feature 4 |
| Structured citation records plus deterministic rendering | Keep model-written IDs visible while validating them against one run-local paragraph map | Optional state fields support resume, logs and re-export; a leaf module can own numbering, validation and notices | Adds state and report annotations; semantic support quality still needs human/live evaluation | Selected for Feature 5 |
| Trust model citations or validate only during export | Minimize state changes | Does not constrain unknown IDs before the next speaker/manager and cannot reliably reproduce resume history | Smaller patch, but weak authority and traceability | Rejected for Feature 5 |
| Local loopback page over the shared graph, event interpreter and report writer | Add a browser view without creating a second analysis implementation | Existing CLI stream and report interfaces can be reused; run-specific artifact paths isolate results | Single-user and local-only; browser behavior still needs manual acceptance | Selected for Feature 6 |
| Separate web analysis stack | Optimize the browser independently from the CLI | Would duplicate event interpretation, model configuration and export behavior | Higher drift and regression risk | Rejected for Feature 6 |
